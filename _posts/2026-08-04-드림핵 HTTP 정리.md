# 1. HTTP
- HTTP :서버와 클라이언트의 데이터 교환을 요청과 응답 형식으로 정의한 프로토콜.

- HTTP 요청
 :시작 줄은 메소드. 요청 대상, 그리고 HTTP 버전으로 구성됨.

- HTTP 응답
 :요청에 대한 결과 반환. 시작 줄은 HTTP 버전, 상태 코드, 처리 사유로 구성.

# 2. HTTPS 
: TLS 프로토콜을 도입하여 HTTP의 보안 문제를 해결.

- 웹 브라우저 : 서버와 http 통신을 대신해주고, 수신한 리소스를 시각화하여 위와 같은 문제를 해결함.

- 주소창에 주소 입력했을 때
    1. 웹 브라우저의 주소창에 입력된 주소를 해석 (URL 분석)
    2. `dreamhack.io`에 해당하는 주소 탐색 (DNS 요청) 
    3. HTTP를 통해 `dreamhack.io`에 요청
    4. `dreamhack.io`의 HTTP 응답 수신
    5. 리소스 다운로드 및 웹 렌더링 (HTML, CSS, Javascript)

- URL : Uniform Resource Locator의 약자로, 웹에 있는 리소스의 위치를 표현하는 문자열. 브라우저로 특정 웹 리소스에 접근할 때는, URL을 사용하여 이를 서버에게 요청.
URL은 Scheme, Authority (Userinfo, Host, Port), Path, Query, Fragment 등으로 구성


| **Scheme** | 웹 서버와 어떤 프로토콜로 통신할지 나타냄 |
| --- | --- |
| **Host** | Authority의 일부로, 접속할 웹 서버의 주소에 대한 정보를 가지고 있음 |
| **Port** | Authority의 일부로, 접속할 웹 서버의 포트에 대한 정보를 가지고 있음 |
| **Path** | 접근할 웹 서버의 리소스 경로로 '/'로 구분됨 |
| **Query** | 웹 서버에 전달하는 파라미터이며 URL에서 '?' 뒤에 위치함 |
| **Fragment** | 메인 리소스에 존재하는 서브 리소스를 접근할 때 이를 식별하기 위한 정보를 담고 있음. '#' 문자 뒤에 위치함 |


## Domain name
- 불규칙한 숫자로 이루어진 IP address는 사람이 외우기 어려우므로, 일반적으로는 도메인의 특성을 담은 이름을 정의하여 IP 대신 사용.
- 브라우저는 DNS에 domain name을 질의하고, DNS가 응답한 IP address를 사용함.
- domain name에 대한 정보는 nslookup 명령어를 사용해 확인할 수 있음.


## 웹 렌더링 
: 서버로부터 받은 리소스를 이용자에게 시각화하는 행위. 서버 응답을 받은 웹 브라우저는 리소스의 타입을 확인하고, 적절한 방식으로 이용자에게 전달함. 
- 사파리는 웹킷, 크롭은 블링크, 파이어폭스는 개코 엔진을 사용함.


## 개발자 도구(Devtools) 
: 웹 서비스 진단하는데 도움이 됨.


- 기능들:
elements : 페이지를 구성하는 HTML 검사
console : 자바 스크립트를 실행하고 결과 확인
sources : HTML, CSS, JS 등 페이지를 구성하는 리소스를 확인하고 디버깅할 수 있음
network: 서버와 오가는 데이터를 확인할 수 있음
Application : 쿠키를 포함해 웹 어플리케이션과 관련된 데이터를 확인할 수 있음
요소 검사 : 특정 요소의 개괄적인 정보를 파악하고, 이와 관련된 코드를 쉽게 찾을 수 있음.

- 디바이스 툴바 : 현재 브라우저의 화면 비율 및 User-Agent를 원하는 값으로 변경할 수 있음.
- Secret browsing mode : 시크릿 모드에서는 새로운 브라우저 세션이 생성되며, 브라우저를 종료했을 때 쿠키, 방문 기록 등이 저장되지 않음. 시크릿 모드로 생성한 탭은 쿠키를 공유하지 않음.

## Cookie & Session

HTTP는 connectionless와 stateless 특징 때문에 웹 서버는 클라이언트를 기억할 수 없음. 그래서 쿠키가 탄생. 쿠키는 Key와 Value로 이러진 일종의 단위로, 서버가 클라이언트에게 쿠키를 발급하면, 클라이언트는 서버에 요청을 보낼 때 마다 쿠키를 같이 전송함.

- 쿠키 변조를 막기 위해 세션을 사용.
세션은 인증 정보를 서버에 저장하고 해당 데이터에 접근할 수 있는 키(유추할 수 업는 랜덤한 문자열)를 만들어 클라이언트에 전달하는 방식으로 작동.

- 세션 하이재킹 : 타 이용자의 쿠키를 훔쳐 인증 정보를 획득하는 공격

워게임 2. cookie

문제의 드림핵 가상서버를 열고 들어간 뒤 개발자도구를 켜고 저장공간으로 들어가고, 쿠키로 들어가서 username, admin의 쿠키를 하나 만들고 페이지를 새로고침 하면 화면에 플래그가 뜬다. 

워게임 3. session-basic

.py로 된 파일을 다운받고 설명을 읽는다. 가상 서버로 들어가서 주소 끝에 /admin을 붙이고 새로고침한다. 
그러면 값이 뜰 것이고, 이것을 원래 주소 들어가서 쿠키 이름은 sessionid, 값은 복사한것을 붙여넣기 하고 새로고침 하면 플래그가 화면에 뜬다.

- Same Origin Policy (SOP) : 동일 출처 정책, 현재 홈페이지의 출처가 아닌 다른 출처로부터 온 데이터를 읽지 못하게 하는 보안 메커니즘

- Cross Origin Resource Sharing(CORS) : 교차 출처 리소스 공유, SOP의 제한을 받지 않고 Cross Origin의 데이터를 처리할 수 있도록 해주는 매커니즘
